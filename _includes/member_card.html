{%- comment -%} Per-member card for the Members page. Expects: include.member — one entry from _data/members.yml (id, name, role, scholar_id, website, image, optional note). Publications are read from _data/scholar_pubs/.yml, which may legitimately be absent — a member added before their first Scholar fetch, or one with no Scholar profile at all — so the lookup is guarded. Jekyll's `sort` filter raises "Cannot sort a null object" on nil input, which would abort the whole site build, not just this card. `concat` against an empty array is what makes that safe: it funnels the value through Liquid's InputIterator, so a missing file (nil) becomes [] rather than reaching a filter that rejects it. The stored order is authoritative and is NOT re-sorted here. bin/fetch_scholar.py writes each file newest-first with a stable sort; Jekyll's `sort` uses Ruby's unstable `Array#sort!`, and the `| sort: "year" | reverse` idiom additionally reverses every same-year group, which scrambled which papers survived `limit:20`. Keep any reordering in the generator, not here. The publication data is auto-refreshed from Google Scholar, so every Scholar-sourced field is HTML-escaped and links are restricted to http(s) to avoid injection. Curated members.yml fields are escaped too for safety. {%- endcomment -%} {%- assign m = include.member -%} {%- assign data = site.data.scholar_pubs[m.id] -%} {%- assign empty_array = "" | split: "," -%} {%- assign pubs = data.pubs | concat: empty_array -%} {%- assign total = data.total | default: pubs.size | plus: 0 -%} {%- assign scholar = m.scholar_id | default: "" | strip -%} {%- assign scholar_url = "https://scholar.google.com/citations?user=" | append: scholar | escape -%}
